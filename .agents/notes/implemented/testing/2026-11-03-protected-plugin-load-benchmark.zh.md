# Agent Note: 受保护插件加载基准

Status: implemented

[English](2026-11-03-protected-plugin-load-benchmark.md) | 中文

## 问题

受保护可执行文件读取会先比较完整插件树，再返回已核验字节。对每个模块重复这项工作，即使单个文件很小，也可能拖慢启动。包内正确性测试没有约束采集与加载的合计开销。

## 决策

[受保护插件基准](../../../../benchmarks/protected-plugin-load/README.zh.md) 在全新的普通 Node 子进程中，通过已构建包的导出测量生产 `ProtectedInputIntegrity`。合成树包含 47 个文件，共 204,279 字节，与已安装 Cordis Loader 包排除依赖目录后的实测文件数和字节规模一致。夹具创建不计入两个计时间隔。采集包含持久记录发布；第二段包含 47 次可执行文件读取，每次都计算完整树摘要。不以仅依赖元数据的捷径替代哈希计算。

每次运行在断言前记录各区间的单次样本、同区间进程 CPU 时间及整个子进程的峰值 RSS。绝对参考上限为采集 250 ms、重复读取 2,500 ms；共享校准再乘 CI 时间比例与波动余量。这些是保守的吞吐上限，不是实测 arm64 中位数，也不承诺单模块延迟。初次 Linux 样本的采集为 4.04 ms、读取为 81.90 ms、峰值 RSS 为 77.61 MiB。该样本只作本机合理性核查，不是跨平台校准。内存只报告，不设阈值，也不按时间比例缩放。

## 考虑过的替代方案

**测量环境中的插件内容。** 每次运行都读取安装目录，会使工作负载依赖本机包版本和内容。固定合成字节保留观察到的规模，不导入环境数据。

**计时复制的摘要函数。** 私有算法副本会遗漏持久记录处理与生产失效检查，因此工作进程调用实际发布实现。

**只按元数据缓存。** 省去摘要读取会测量不同的信任判定，并可能漏掉字节变化。身份变化、链接根竞态和审批拒绝由行为测试负责；基准保留完整内容比较。

## 影响

基准检测采集和重复读取中的大幅吞吐回退，并保留原始证据供日后收紧预算。它不包含 owner 回答时间、模块执行、网络文件系统、依赖图深度、Worker 启动及对抗性并发写入。平面目录树只模拟字节与文件数规模，不代表所有文件系统拓扑。正确性与竞态覆盖保留在 app-boot 测试中，不重复为计时断言。
