# 孤窗开场恢复

[English](guide.md) | 中文

## 变更

seat-local 恢复在确认原持有者死亡、资源释放并隔离后，自动撤回尚未领取的首轮交接并归档窗口；此前此类窗口等待人工收窗。既有 `opening-failed` 细因 `seat-local/opening-owner-lost` 先于 `window-ended`，没有新增窗结束原因。冻结人工开窗及来源唤醒保留原因 `manual`，使用细因 `restart-manual-opening-closed` 或 `restart-source-wake-closed` 并显示本地化工位告警，不自动重派。其他孤窗收窗保留原因 `owner-dead`。已领取、已注入的输入及所有权未知的情况仍不适用。

来源所有者组合可依据已认证的失败与收窗证据及已释放预约，授权一次持久重派。仅本地收窗不允许重放效果未知的投递。启用此行为时，执行端与来源所有者须成对部署。

## 迁移

1. 升级前停止新来源准入，备份执行端与来源所有者的全部持久域，保留双方版本及恢复水位。
2. 先恢复来源所有者，再启动执行端。保留回调路由、认证账号及原操作身份，不清除待处理回调或开场投递。
3. 确认符合条件的孤窗只有一次失败与一次窗结束回调，原投递已撤回，且预约先于任何重派释放。确认已领取输入不变、未知结果只按原键查询。
4. 回退前停止准入，先对账全部回调及后继代次。旧严格读取器无法读取含自动重派审计字段或两种重启收窗细因的持久域。只有核算升级后的效果后才可协调恢复升级前备份；不得单边恢复，也不得清除重试计数以续做工作。
