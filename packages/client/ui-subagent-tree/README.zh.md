# @panedesk/dsh-client-ui-subagent-tree

[English](README.md) | 中文

## 概述

从会话头在右栏打开本会话的子代理树。嵌套行展示状态、模型、token 合计与缓存命中率。点击行或其监测按钮打开详情。内置子节点详情包含与子代理图相同的实时任务预览和「打开子会话」操作，在右侧 Sidebar 打开子会话而不替换主会话；根节点和外部节点仍只提供监测。监测事实包括只读状态（在跑、等待或结束原因）、模型、五类 token、缓存命中率、已用时、最近工具调用及其时刻、所属位与关联单。运行中的行提供红色「停止」按钮，无需确认；按子孙优先顺序中断所选会话及其运行中的后代。运行与等待节点显示绿点，静默节点显示灰点。模型名使用共用五色：Claude 蓝、GPT 橙、GLM 绿、DeepSeek 琥珀色、其他模型粉色。内置子代理标签以 `提供方 · 模型 · 档位` 展示会话转录中最近观测的请求头或助手响应（档位仅在请求头声明时附注；路由未配置档位启动时显示 `档位不适用`），不从账本配置默认值回填；模型家族配色忽略提供方。外部模型名来自派遣登记；缺失保持未知。

外部登记表设置的操作使用共用有边框按钮。树顶「验证」快捷入口打开工作区设置。运行中的原生子代理行提供「禁止再测试」：仅对本次运行拒绝后续改动面、全量、变异测试及自写脚本，不停止正在执行的操作。取消勾选仅移除该行限制，清单与工作区限制仍保留。确认后的状态在下一次树刷新时显示。

监测详情包含该会话的验证清单：每条已提交的检查项显示预计分钟和观察到的类别用时，工作区已关闭的类别标灰，跑过但未申报的类别标为未申报。原生节点行显示当前类别与已用 `mm:ss`，空闲时保留上一类。监测详情保留每任务各类次数、累计用时与占比；树提供全树合计，输入区底栏将父窗表放在上下文用量旁。四处视图复用同一树资源及活动服务的持久账本事实。「Panedesk 特色设置」页可选择工作区编辑命令含文字规则，缺省空表，按规范工作区路径存入 `activity-category.projects`。外部登记节点不归类；藏在新写脚本中的测试挂自写脚本标记，远端 CI 只显示推送或触发。自写脚本用时与主类重叠，不重复加入分母。

## 使用本包

紧凑的 28px 药丸保留既有头部高度，只出现在已打开会话的头部动作区，排在子代理目录药丸之后；`minimal` 预设不显示该入口，不占首屏，也不上引导页。点按后在右栏以 `subagenttree` 页签类型打开本会话的树页，资源地址 `dsh-resource://subagenttree/session/<sessionId>`。页签按部署配置的节拍轮询 `subagentTree.read` Remote，并以中英文案渲染八态（默认、加载、空、错误、无权限、禁用、成功、失败）。节点行按树深缩进，前置状态点，标签取会话投影（缺失回退会话号）。已完成使用成功色，已停止或已取消使用警示色，并保留不同文字标签。行与监测详情以最近一次已报告请求的上下文（未缓存输入加缓存读写）为主，后列这些桶与输出的累计用量。缺少逐请求上下文时保持未知，包括仅有累计的外部记录。监测事实逐项给出数值或明示未知；用量证据覆盖（无 / 部分 / 完整）如实展示，不填零。

「Panedesk 特色设置」页提供**外部子代理登记文件**，值以 `ui-subagent-tree.externalRegistryFile` 和 `externalRegistryEnabled` 全局保存在活动 profile 的 `cordis.patch.yml` 中。外部读取缺省关闭；关闭开关时保留路径。填写你的派遣脚本使用的、主机可读的 UTF-8 JSONL 文件；路径修改立即保存，非空路径同时启用。桌面端「选择文件」使用窗口持有的 Electron 文件选择器，保存所选绝对路径；Web 不提供选择器。三步初次使用说明介绍准备文件、填写路径和查看树页；AI 请求通过 `panedesk_settings` 读取并修改两项登记偏好。该行显示登记文件与配置文件的路径、所在目录，并提供就地打开文件和目录操作。每次刷新读取该文件，跳过无效行，按 `子会话号` 保留最后一条有效记录，再筛选 `父会话号` 等于当前显示会话的记录。外部节点带标记，作为叶节点与内置子节点同列。标题取 `短题` 或 `类型`，模型取 `实际模型` 或 `模型`，监测视图优先展示 `起止时刻.起` / `起止时刻.止`，缺失时取 `起` / `止`。`在途` 表示运行中；缺少 `状态` 按结束处理；结束记录仅在 `退出码` 为零时显示完成。Token 总计为 `用量` 中各模型的 `inputTokens + outputTokens` 之和。文件不可读时显示警告，但不隐藏内置节点，后续刷新会重试。已打开的监测弹窗跟随刷新后的数值。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内部——点击展开</summary>

宿主提供已认证所有者读取接口 `subagentTree.read(request)`，以及停止最新外部登记行中 `启动器PID` 与 `PID` 进程树的 `subagentTree.stopExternal(request)`。Windows 使用 `taskkill /PID <pid> /T /F`；其他系统先向进程组发送 SIGKILL，必要时再停止单个进程。停止成功后复制登记行追加写入，改为 `状态: "结束"`、`备注: "停道:主窗手动"`，并在 `起止时刻.止` 写入本地 ISO 时间。浏览器通过注入的 `subagentTreeUI` 与图共用模型色与子孙优先的原生停止逻辑；逐子节点调用 `subagents.interruptByParent`，根节点调用 `session.cancel`。应答仅表示中断已接收，刷新后的终止事实显示「已停止」。树直接读去重后的 `sessionLedger` 快照（不改 `ledger-query`）：成员资格沿能到达请求会话的 `parentSessionId` 链，环退化为排除，账本行序即观测序。逐会话 token 列对带用量的调用结束求和；短档写仅在调用可证分档缓存写时存在，未分档写只保留总计；缓存命中 = 缓存读 ÷（未缓存输入 + 缓存读 + 已观测写），零分母为未知。状态在最新驻留有结束帧时为 `finished` 并带账本结束原因，否则有未配对 `wait/start` 时为 `waiting`，否则仅在最新运行已开始且未结束时为 `running`，其余为 `idle`；存活来自进程观测。会话自身轮次结束后，仍驻留的运行或等待状态显示为空闲；中断轮次显示已停止，直到新轮次开始。仍驻留且有活跃后代的父级保持等待；仅有可续话的空闲收件箱不算活动。图卡用同一事实判定绿点与停止按钮，因此完成轮次显示灰点且没有停止按钮。内置派遣在执行前写入关联父会话的运行开始记录，结算后保留结束记录，按预设类型派遣也走此路径。模型号与最近工具调用经 `sessionQuery.readSession` 折叠会话自身日志后缀，跳过 fork 继承前缀；请求头在首次助手响应前提供已观测路由，随后以响应报告的模型为准；`sessionQuery` 缺失标记模型不可用，日志不可读标记不可读——两者在线上均保持未知。

</details>

<a id="model-experience"></a>
## 模型体验

### 只读会话树

#### 模型看到什么

无。`subagentTree.read(request)` 为客户端界面读取账本与转录；不发送任何提示段，不调用面向模型的工具。

#### Token 影响

无。读取不增加任何模型 token。

#### KV 缓存影响

无。读取从不改动请求 token。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **转录读取串行且无上限** —— 每次读取按账本序逐节点经 `sessionQuery.readSession` 读自身日志后缀；树越宽单次读取越慢，暂无逐节点上限。
- **等待按等待对计数** —— `waiting` 比较未配对的 `wait/start` 与 `wait/end` 辅助事实；从不配对等待的提供方会显示 `running`。
