<a id="behavior"></a>
## 行为

会话浮层等待当前欢迎提示已确认、主会话就绪且不再为空白，再按工作区路径询问一次关、只提醒或自动；自动是初始草稿，不代表隐式批准，保存生效后可能产生模型费用。成功选择保存在产品档案的 `ui-project-onboarding.projects` 字典中，不写用户项目。项目开窗设置页列出已有工作区和已存目录，无需进入项目会话。页面解释各档行为和自动缺省档，点击档位即保存。页面展示产品配置和 JSON 工位档案的文件与目录绝对路径，提供宿主原生打开和定位动作，并可显式刷新引擎的在跑、恢复中或不可用状态。工位档案包含本机所有项目；本地服务缺席或使用非 JSON 后端时没有可打开的本地档案文件。项目级可调偏好只有开窗档位，引擎部署参数仍由宿主管理。只读设置禁用写入；失败保留先前可见选择并提供重试。

Panedesk 共用页头提供三步初次使用说明，并明确档位修改只能手动。产品偏好保持可见，引擎观察和工位目录收进**高级(单机用不着)**。

仅所有者可用的 `projectOpening.select` 从完整且已授权的本地席目录解析匹配项目，以修订号检查应用引擎策略，再持久化产品偏好。保存失败后，以本次保存拥有的修订逐项尝试恢复，包含原 `modeChosen` 标志。不会覆盖并发赢家；若并发恢复已经与原字段一致，则计为已恢复。结构化结果与本地化反馈逐项报告已恢复、冲突或失败后结果不明。

没有匹配席时仅存偏好，不启动引擎。由插件生命周期拥有的同步解析器，在引擎首个准入事务内读取工作区已存选择，覆盖新导入席。策略与准入或禁用拒绝一起提交，不靠事后通知修补首个决策。项目显式策略优先；同一席的多个目录若有互相冲突的已存选择，则拒绝准入，不任意选一个目录。卸载插件只移除解析器，不删除已经提交的策略。

设置 → Panedesk → 工作流编辑产品偏好 `workflowRequirementsPrompt`、`workflowSetupPrompt`、`workflowCheckupPrompt` 的本地化开窗词，每句提供保存与恢复缺省。缺省分别引用内置 workflow-pack 的 `requirements-review.md`、`getting-started.md`、`workflow-checkup.md`（中文使用 `.zh.md`）；开局需要 Python 3.11 或更新版本。项目引导使用已存的搭建工作流句。空会话首屏通过 `conversation.hero.starters`，将核对产品需求、搭建工作流、优化工作流三个可选入口及其标题句居中放在欢迎标题上方。点击后插入已存开窗词、保存草稿并聚焦输入框，不发送、不写项目文件。选择后在输入框上方保留「换一个入口」按钮，点击清空刚插入的草稿并恢复三个入口；右上工作流菜单插入开窗词后也显示此按钮。未选择前直接打字或发送消息后，中央入口收起。工作流页管理 `ui-project-onboarding.showWorkflowStarters`，缺省 `true`；只控制中央入口，不影响右上菜单。

开窗词预设保存在缺省为空列表的产品设置 `ui-project-onboarding.openingPresets`。设置 → Panedesk → 开窗词预设显示实际配置路径，并复用设置文件打开动作。「添加 / 编辑预设」在列表为空时也能打开，与右上添加预设入口共用编辑器初始化逻辑，空列表会展开一条新预设。编辑器支持添加、编辑、删除预设，包括产品档案中已有的条目。保存成功后编辑器保持打开，在保存按钮旁显示「已保存 N 条」，四秒后消失，立即更新设置页列表、重新打开的编辑器和新会话的「开窗词」菜单；重启后已存条目仍可用。每条缺省折叠成把手、名字、第一个目录和带无障碍标签的删除图标的一行，展开后编辑。只有把手能拖动，拖影使用半透明窄条，落点显示插入线；也可用上移、下移排序。拖文件夹仍添加到目标条目。在任一开窗词框粘贴至少两行非空文本，会在原位置拆成每行一条，按现有截取规则起名，目录优先推断，推不出则沿用该条已填目录。列表上方的提示提供撤销，将粘贴的多行原文合回原开窗词框。单行粘贴保持原行为。批量粘贴区位于列表上方，也支持 markdown 表；表头识别「开窗目录」「开窗句原文」/「开窗句(原文)」及可选模型、权限列。每条保存的预设包含名字、开窗词原文和至少一个目录。桌面拖文件夹复用宿主路径桥，添加文件夹使用原生选择框。批量导入从 markdown 所在文件夹的上一级及其直接子目录匹配已存在的注册工作区；无匹配时留空编辑，补齐目录才能保存。手动新增与导入共用通用设置的名字截取规则，其次使用所在文件夹名或开窗词文本，含省略号在内最多二十个 Unicode 字符。

「开窗词」菜单占原模式选择器位置，模式选择器位于该行最右。当前目录匹配项排前，其余按第一个目录分组；当前目录不匹配且配置多目录时使用二级菜单。选择后复用目标工作区的空白会话，替换草稿但不发送，应用可选模型 / 权限并聚焦输入框。模型接受目录中的模型 ID 或 `provider/model`，空格或 ` / ` 后可附档位；权限填已装配的 `/permission` 档名。未填的项保留接收会话的当前设置。选择时通过既有标题事件记录预设名，沿用开窗日期与同名编号规则。新会话首屏通过 `conversation.hero.actions` 在品牌标上方偏右并排放置开窗词预设与工作流。开窗词预设直接展示同一排序清单，添加预设打开编辑器时只展开位于首条的新预设，已有条目折叠在下方，管理直达其设置分区。工作流提供同样三项草稿动作与设置跳转。两处跳转复用 `settingsNavigation.openSection`；中央入口关闭时两个菜单仍可用。编辑配置与选预设不发模型请求；模型与权限选择在用户发送时生效。

<a id="dev-note"></a>
## 开发备注

宿主偏好与席策略同步位于 `src/index.ts` 和 `src/opening.ts`；客户端入口位于 `src/client/`。客户端读取与失效刷新使用共享设置描述镜像；成功选择的回复折回该镜像，不另发描述请求。预设设置页、编辑器与选择器共享同一个 `configForms` 实例；预设 schema 使用可序列化字段，因为客户端会重建 schema 并校验镜像值。

<a id="model-experience"></a>
## 模型体验

### 项目引导

#### 模型看到的内容

查看或保存 `ui-project-onboarding.projects` 偏好不增加模型上下文。工作模式包动作在用户发送前只修改可见草稿。

#### 令牌影响

查看或保存偏好不发模型请求、不消耗模型令牌。自动档可能允许后续规则驱动的模型工作。

#### KV 缓存影响

用户发送草稿前，本包不改变提示前缀或保留的模型历史。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 工作区键是宿主目录路径；别名和符号链接不合并。共享同一精确目录的席项目接受相同的明确选择。
- 产品持久化和引擎日志是独立存储。报告回退冲突时需人工审查策略；不承诺跨存储原子性。
