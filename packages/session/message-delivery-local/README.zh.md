# @panedesk/dsh-message-delivery-local

[English](README.md) | 中文

## 概述

本地文件信箱位于产品家目录下的 `messages/nodes/<nodeId>`。插件登记已持租约的 agent（智能体），发布运行时忙、闲及关闭中状态，并在资源释放后撤销登记。会话写租约始终是真源；注册不会获取或抢占租约。提供方重载会在新代际中幂等重登记现存 live Agent，不接管未发布或正在结束的 Agent；旧代清理不能移除新登记。参见[会话持久化](../../../docs/subsystems/persistence.zh.md)。

## 寻址与分页

设置 `pagination: true` 时，提供方签发的游标对未答消息分页，前页条目变为终态也不重复返回前页。保持筛选条件不变；不可用游标和非正安全整数限额会被拒绝。否则忽略 `cursor`，`limit` 使用 JavaScript `slice(0, limit)`，`complete` 比较匹配条数与限额，且不返回游标。

设置 `seatAddressing: true`，通过 `seatLocalRead.messageWindows` 启用可选的精确位解析与在线观测。省略时位寻址保持关闭，会话号／标题寻址不变。仅纳入本地在开且运行时存活状态明确的窗口；多窗时解析唯一主窗，否则返回歧义原因及候选。未开位返回 `seat not open`。显式组合与时序参见[位消息工具](../tool-seat-messages/README.zh.md)。

远端精确位入站使用同一显式开关和宿主持有的完整信封验证。缺少定义返回 `target-not-found`；已有位但没有本地存活窗返回 `offline`；忙窗的收件政策拒收时返回 `busy-not-accepting`，忙本身不拒收。接收器先固定解析出的会话再追加信箱，保留原消息身份，不将留存尝试改投替代窗。节点在线查询串行执行，最多检查 `maxBatchSize` 个对端，以委托有效期为超时；失联或超时的对端保持未知。观测不是预留。

<a id="dev-note"></a>
## 开发备注

配置可选提供 `nodeId`；缺省时，若存在 `messageLedger` 服务，启动通过其 `nodeId()` 解析持久节点身份；否则通过 `sessionLedger.nodeId()` 解析。身份不可用时诊断并停用投递，不阻止宿主或旧智能体路径启动。配置显式提供 `maxRecordBytes`、`maxContentBytes`、`maxBatchSize`、`lockTimeoutMs`、`lockRetryMs`、`scanIntervalMs` 与 `watch`；可选的 `dshHome` 覆盖产品家目录。限额均为正整数，扫描间隔不得超过一秒。与 `agents`、`sessions` 和 `sessionPersistence` 一同挂载；可选的 `subprocess` 与消息账本提供方提供平台身份和回执记账。

存储布局：每个目标使用 `mailboxes/<sessionId>/publish.lock`；`operations/` 保存 `<operation-key>.lock`、`routed.lock` 与 `receipt-order.lock`。这些专用文件独立于可读记录和回执。Linux 与 macOS 保持原描述符 flock、校验及重试循环。仅 win32 使用独占共享打开，对 `EBUSY`/`EPERM` 从 `lockRetryMs` 退避到 40 毫秒，在 `lockTimeoutMs` 上限内重试；超时报告 `EAGAIN` 与锁文件名，不含路径或内容。锁文件内容从不读写；关闭句柄或进程退出即释放所有权。不得删除或替换锁文件。

每条记录采用排他临时文件创建、带版本及长度／摘要的封装、文件同步、原子发布及 POSIX 目录同步。每目标原生锁串行发布，并以明确的跳过区间恢复高水位。Linux 信箱目录与文件要求仅属主可访问，并拒绝符号链接。产品家目录必须属于当前用户、不能是符号链接，且不能允许其他用户写入；仅当目录组是当前用户主组，且系统名称服务枚举确认没有其他附加成员或以该组为主组的用户时，允许组写入，并在提供方初始化时诊断一次。组成员信息不可查时拒用信箱。不修改既有权限。Windows 在初始化存储前核验继承的 DACL 授权；其他主体的读写授权会被拒绝。未知进程身份保持不可用，绝不据此回收会话。

同一提供方生命周期内，回执持久发布与账本追加均成功后，输入准备不再重复发布或追加该回执。追加失败仍可重试；提供方重载按原持久身份重放留存回执。

相同本地发送仅在信箱准入前被拒绝且没有待定副作用时，才可重新解析缓存的 `unavailable` 暂拒；请求摘要仍须匹配。已接受、目标关闭但已入箱待定及结果不确定的发送保留原操作身份与信箱去重；更改载荷会冲突。

路由拒绝保留旧外层原因，并可通过持久回执解码保留原始节点链路原因。原因码为有长度上限的 ASCII 标识；说明非空、无控制字符，且不超过 512 个 UTF-8 字节。生产方必须在传输前清除秘密与地址。未知结果保持未知；缺少原因时不补默认值。非法诊断会被拒绝，不截断或静默丢弃。

路由发送在运输前被拒后，同一操作号保持终拒。发中不确定保留完整冻结消息与投递身份、`phase: 'unknown'` 及原主体／会话／席位／任务关联。扫描循环每轮最多检查 `maxBatchSize` 个目录项，以提供方持有的游标公平续扫，隔离单条记录失败，并在资源释放时关闭游标。只在原 agent 仍存活且被接管时恢复会话发送，重新进入其发起者作用域并取得新授权。恢复显式请求认证的原键回执，即使本地路由记录缺失也须查询；只有精确 `missing` 才允许交付冻结载荷。待决、查询失败、授权变化和生命周期停止均不允许重放。人类发送须在原受信入口显式重试，持久 sender 字符串不能重建人类权限。旧记录仍可读，但缺少留存授权的记录不参与后台恢复。回退前停止准入并保存全部未决信箱与运输记录；旧程序不实现这些恢复保证。

## 模型体验

### 本地注册

#### 模型看到什么

投递消息保留发送方铸造的身份，通过 `user/message` 进入模型。作废保留原历史，并另行排入包含原号与原因的 steer 通知。回执不进入收件箱。

#### Token 影响

投递正文与作废通知消耗输入 Token；注册与回执不消耗。

#### KV Cache 影响

新投递输入扩展请求历史。作废追加通知，不重写原有模型可见前缀。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 服务在队列入队前裁决发送与控制，留存控制结果供重放，并在恢复投递前还原持久输入阶段。宿主必须保持会话租约获取、释放与 agent 生命周期的顺序。改档依赖支持优先级的队列实现。
- 政策由 `sessionProjections` 从持久 `message/settings` 事件投影，支持不写检查点的宿主冷读。`handoff-only` 收回复、拒知会；属主复核新消息政策，但不清除已接纳输入。开关开启时，闲态交接与回复显式请求调度器唤醒；知会保持被动。清单试算不写信箱、不唤醒，同一解析会话只发一次。回执订阅按发布顺序游标续取，不进入收件箱。属主测试使用调度替身；真实 headless 组合、父子隔离与内核唤醒保证仍需集成验证。
- 精确远端会话发送要求同时提供 `nodeRouter` 与 `nodeDelegationIssuer`，否则保留既有本地行为。发送身份在传输前冻结；本地路由接收器验证宿主能力，回复前保留原始信封与回执；相同重投复用原回执，身份冲突拒绝。普通发送接口不提供工具调用或交接因果证据，须由受信上游组合提供，不能编造标识。远端普通发送在路由前拒绝调用方添加的 `callId`、`rootCallId`、`causedByDeliveryId` 和 `delivery` 字段，不能将自报因果升级为受信信封。
- Windows 发布、身份与权限路径需要平台验证;Linux 测试只覆盖注入的 Windows 证据。同一用户的恶意进程不在存储隔离保证内。
