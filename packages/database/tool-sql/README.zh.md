# PostgreSQL 内置工具

`sql` 工具使用 `ctx.databaseConnections`，不需要 MCP 服务。缺省基础 bundle 已装配，但至少一个连接开启 **让模型可以查这个库** 后才出现在模型工具列表。

## 三项能力

用保存的连接名称选择数据库。`list_tables` 列出用户可见的 `schema.table`；`describe_table` 接受 `table`，返回列名、PostgreSQL 类型、可空与主键标记，大小写敏感名称按 SQL 规则引用；`execute_sql` 接受 SQL 并返回行。不额外限制为只读，所有权限取决于 PostgreSQL 账号。仅向模型开放权限符合预期的账号。

所有者开关同时控制 schema 枚举，并在执行时再次核对。改名或切换开关会重建工具定义。每次调用独立开连接，遵循调用方取消信号，并在 `finally` 关闭客户端和 SSH 转发。原生与 PTC 调用均走现有工具注册机制。

## 输出

逐行返回 JSON。`maxRows` 缺省 `200`，`maxCharacters` 缺省 `32000`，包含预留的摘要空间。驱动执行完查询时持续丢弃超限行，末尾明确注明总行数、返回行数、受影响或报告行数及是否截断。不会悄悄给 SQL 改写 LIMIT。单行过长则整行省略，不切出无效 JSON。错误使用现有工具错误呈现，通用工具卡显示参数与结果。

## 模型体验

开启第一个连接会增加一个工具 schema。改连接名会改变 schema，可能影响提示词缓存。只暴露已开启连接的名称，凭据与网络配置不进入模型提示。结果按配置上限消耗 token，并明确报告截断。

## 已知限制与后续工作

统计总行数需要读完整查询响应，即使只保留少量前缀。数据库查询本身仍可能耗费大量时间或内存，单行也须先解码才能按输出上限省略。取消会断开客户端，但不能撤销已经提交的 SQL；重试写操作前应检查数据库状态。事务须在一次调用内完成，因为调用间不共享句柄。本交付未进行真实数据库或 SSH 验证。
