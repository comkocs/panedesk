# @panedesk/dsh-seat-engine

[English](README.md) | 中文

## 概述

通过独立日志、持久队列、资源所有权和回调发件箱实现[席位引擎服务](../../../docs/subsystems/seat.zh.md)。安装必须显式进行；普通配置方案不会启用自动开窗。

## 使用本包

外部规则精确匹配 `sourceId`，配置了 `eventType` 时也精确匹配该值。有外部规则但未命中时不得退回项目自动模式；没有外部规则的档案保留旧行为。配置了外部规则时，合并区分外部来源及事件类型；开窗引用始终保持分离。可选来源引用要求已注册来源及兼容的本地冻结器；接纳快照在确认之前随既有决策事务保存正文、摘要、版本及任务关联。来源游标仍归适配器，必须在持久接纳后才推进。

以完整 `Config` 和 `sessionLedger` 提供方挂载插件。账本提供节点身份；`home` 选择隔离存储。激活前验证字节、批次、去重、回调及恢复限制为正值。所有者观察间隔最多一秒；观察、释放及队列唤醒预算合计不得超过五秒。预算或节点容量限制缺省表示无限制，不代表自行设定配额。

通过 `failureRecovery: { retryInitialMs: 1000 }` 显式启用运行时失败监督；省略时保留状态锁存与既有调度。初始延迟必须是 1 至 300000 毫秒的整数。已知传输码（`ETIMEDOUT`、`ECONNRESET`、`ECONNREFUSED`、`EPIPE`、`node-tunnel-disconnected`、`node-deadline-exceeded`、`callback-timeout`）按指数退避重试，上限五分钟。只有包含回调结算与决定通知的完整 drive 成功，才清除可重试失败。决定监听器可能再次收到同一个已提交决定，必须按其身份去重副作用。监听失败不回滚已提交决定。监听器发起的写入在提交后返回，不等待自身通知；串行发布器在当前监听器结束后继续发布这些决定。通知之外的并发调用仍等待发布器。回调重试保留既有载荷、键与未知结果查询屏障。

路由回调监督保留观测阶段、重试许可与业务效果界限。`unavailable` 拒绝仅在明确给出 `retryable: true` 且 `effectState: none` 时重试，包括路由服务或签发器暂缺。`cross-node-unsupported` 仅在 peer-query 或 peer-dispatch 阶段带有 `peer-capability-missing`、明确重试许可且无效果时重试；不放宽准入及方法拒绝。部分生效、已提交、未知或缺失的效果证据均不授权自动重放；诊断不能弱化返回结果的效果界限。即使提供方标记可重试，状态及协议冲突和未登记码仍保持停止。仅携带异常的持久化失败不会被重分类为路由暂缺。本地来源缺席仅在注册处尚未进入回调便拒绝时重试；适配器内部抛出的同码不能证明无效果。签发器阶段的 `unauthorized` 拒绝在确认无效果且无身份冲突时，仅将该回调停车等待操作员处置，不停止引擎，也不阻断独立链上的其他回调；同链顺序仍保留。`node.status.callbackFailures` 投影这些停车拒权，供所有者即时告警。恢复原账号后，使用既有 `engine.callbackResolve` 恢复或放弃；退出停车态后清除告警，不删除审计事实。路由服务暂缺仍可重试；效果歧义、身份冲突及持久化失败保留既有监督。

开窗时的 `invalid-definition` 拒绝（包括本地异常嵌套的 `failure.code`）仅将该工位开窗结算为 `opening-failed`。创建失败只有在持久态确认不存在会话后才释放资源；后续阶段保留部分效果。开场消息已发送而定义错误阻止结果观察时，保留消息身份与未解决状态；监督停止，不虚构终态。其他工位和引擎继续运行。告警写明工位，提示修好定义后重开；修改该定义或成功打开同一工位后清除告警，不移除审计事实。

`callback-authentication-failed` 拒绝只有在保留的效果证据明确为 `none` 时才仅将该回调停车。引擎和独立回调链继续运行，同链顺序不变。修复认证后，通过 `engine.callbackResolve` 恢复或放弃；恢复动作保留已确认的无效果证据，直到下次投递产生自己的结果；离开停车态后清除本地化回调告警。部分、已提交、未知或缺失效果仍按证据歧义停止受监督的驱动；后来的认证拒绝不能抹掉先前的不确定结果。

账本争用仅在 `LEDGER_UNAVAILABLE` 带有 `lockTimeoutCode: LEDGER_LOCK_TIMEOUT` 时重试；该标记在写事务开始前设置，并穿过账本包装。写入及同步失败保留既有分类。重试保留原开窗与消息身份。启用失败监督时，可重试的回合准入查询异常会登记该会话，待完整恢复轮次后重新检查；获准的排队输入无需新消息即可自动续跑，仅有被动输入仍不起回合。运行时失败变化及已提交决定发布不带正文的诊断失效通知；`node.status.openingFailures` 投影每个工位最近的未创建失败，直到后续成功开窗，不将失败意图当作 Session。缺预设失败保留 `details.agentPreset`，供所有者本地化报告。模型配置拒绝保留 `details.provider` 与 `details.model`，也显示于 `openingFailures`，但不把已有 Session 声称为不存在。

未分类失败额外记录 `exception` 数组，包含异常、cause 与聚合成员的构造器名及 `name`/`code` 标识，最多四层、十六项。每个标识最多 48 个字符，仅允许 `[A-Za-z0-9._:-]`；不安全或令牌样标识省略。摘要绝不读入 message、stack、URL 或路径。它仅进入日志，不影响分类，也不扩展 `node.status` 或持久化记录。

每次引擎失败通过 logger 与 stderr 输出一行安全错误，包含位置、细因码、可重试性及处置；`node.status.failure` 提供 `site`、`code`、`since`、`retryable`、`attempts`，不包含异常正文。连续不可用严格超过十分钟时再输出一次错误，设置 `failure.unavailableOverTenMinutes` 并使所有者诊断失效。本地化告警复用既有工位诊断区，引擎恢复 running 时随 failure 清除。状态冲突、证据歧义、持久化不确定、保留注册缺失或歧义、所有者释放重试耗尽及未分类失败会停止受监督的 drive。后续传输暂态不能清除这些失败。修复底层证据或配置、停止准入、排空并重启宿主以重放日志；目前不提供 `engine.recover` 命令。不得通过删日志帧或绕过授权清除状态。诊断仅存在于运行时，不改变业务记录；卸载会取消告警计时器。

所有者释放保留 `ownerReleaseBudgetMs`，作为每个所有者观察及释放的耗时护栏。超出时结束当前释放批次，并报告 `owner-release-budget-exceeded`。启用监督时，`failureRecovery.ownerReleaseMaxAttempts` 限制连续不可用期间的尝试次数；它是正整数，缺省为三次，沿用配置的指数退避。耗尽后停止自动恢复，并保留即时的引擎停止诊断。已提交的释放不会重复。

模型配置阶段的结构化 `session/model-unavailable` 仅为该 Session 记录 `open-configuration-failed`，其他工位继续运行。恢复模型后，在同一 Session 重发输入。显式回合准入串行重试剩余配置，成功后清除诊断，不会再次发送原开场。死所有者已释放的暂缓活会话，必须具备匹配的持久身份、明确存活证据、新 epoch、可用容量及预算，且没有关闭屏障或终态关闭，才能重新取得资源。原独占标签仍为必需条件；不能仅凭持久态观察复活已死或未知会话。

活窗 `UNKNOWN_MODEL` 与 `session/model-unavailable` 错误为精确的 Session 及其保留工位发布运行时诊断，使用本次尝试请求的模型，而非工位缺省模型。其他工位与引擎继续运行，开窗状态及回合错误分类不变。恢复模型后在原窗口重发；回合成功完成或运行时释放后清除对应诊断。子进程恢复屏障保留 IPC 句柄，直到所属测试终止该子进程。

存储布局：节点日志在 `events/` 旁保留 `owner.lock`。Linux 与 macOS 保持既有描述符 flock 和争用即失败语义。仅 win32 对此专用锁文件使用独占共享打开，在 100 毫秒内以 10–40 毫秒退避重试。锁文件内容从不读写；关闭句柄或进程退出即释放所有权，不得删除或替换锁文件。启动失败诊断包含错误码，不含路径或日志内容。

项目策略默认 `remind`，且 `modeChosen: false`。每次进入待批准状态时，与待开项一起提交一条 `queue/reminded` 提醒事件；合并、重投与重放不重复该提醒。批准仅取消提醒确认要求；容量、时间窗、独占资源及预算检查仍然生效。不完整的成本证据阻止准入，不能按零计算。本地执行器拥有会话副作用；引擎在恢复中保留原意图标识，绝不盲目重试结果不确定的模型请求。

在线与离线待批分页可选公开冻结标题 `windowName`、冻结链目标 `nodeId`，以及首个来源所匹配冻结规则的 `budget`。缺失证据保持缺席，包括非链条目的节点标识；零限额仍显式保留。脱敏仍移除冻结指令及来源原始数据。批准与实际开窗进度保持分离。

并发 drive 调用在当前轮次结束后等待新的协调轮次，避免新接纳工作遗漏于该次确认。成功轮次结束或被暂缓的 Agent 返回闲态后，对回合曾被暂缓的席位 Agent 重新检查准入，仅在允许时显式唤醒；预算停止或证据不可核验时仍阻止回合。创建返回结构化 `agent-preset/not-found` 且再次确认会话持久态不存在时，仅以 `open-create-failed` 终止该开窗并释放资源预留。其他失败保留既有监督与不确定性规则。

接纳的开窗在排队与恢复期间保留定义、标题及渲染文本；当前项目和规则模式限制仍然生效。人工预填配置原会话，但不发送模型请求。开窗进度不能回退已提交的预算修订。本地提供方注册仅供引擎使用的列窗与收窗能力，不放宽外部权限校验。关闭屏障保留操作身份；换窗终态摘要冲突在追加前以 `state-conflict` 拒绝。

收窗事实与窗结束回调可选保留 `detail: 'approval-pending-cancelled'`，结束原因枚举不变。旧记录缺此字段时保持原意，严格旧读器拒绝带此字段的记录。升级前停止准入并保留执行端与来源所有者完整持久域；写入细因后不得降级在线持久域。Session 格式版本不变。

Loader 注册 `subagentAdmission`、`subagentNotifications` 与 `jobNotifications`。绑定席位的父会话使用定义中的子代理容量和子自身的缓存、上下文证据。完成记录位于节点日志的 `notifications` 目录；job 意图在生产副作用前同步写入，待交付的 handoff/steer 消息复用稳定操作标识。恢复中的未结算 job 报告所有者丢失、结果未知，绝不重放外部工作。单条完成通知失败时保留待投递状态，不阻塞其他父会话；重试复用原观测及消息操作身份，成功投递不重复。通知存储写入结果不确定时，停止依赖该存储的接纳及投递，直到重新打开并恢复；已在途发送保留原结果与操作身份。

显式 `sources` 配置调度记录、登记的 Git 路径与引用、窗口结束观察及未答复交接期限。启动在启用 `seat.open` 处理器前对账持久动作与配置来源：记录变化时删除再创建，记录不变时保留下次触发时刻，payload 指向已删除来源的动作会被删除，即使 `sources` 为空。比较使用规范化后的记录字段，并计入上次回执后的周期推进。其他动作名不受影响。替换和删除分别记录 `Seat schedule source reconciled` 与 `Seat schedule source removed`；失败通过 `Seat schedule registration failed` 告警，不阻断宿主，但处理器保持不可用，直到重启对账成功。替换不是原子的；删除后失败会使动作缺席，直到下次对账。Git 只读取登记仓库。人工入口仍归本地提供方，签名外部入口归远端提供方。这些观察源的回调是本地确认，不是出站 HTTP 回调。

本地执行策略可在受理时要求持久化 `recheckRequired` 标记，并在派发及恢复未完成开窗前复核原队列输入。只有可信复核明确返回 `retryable=false` 且 `effectState=none` 才取消队列并要求重新预检；可重试、未知或不可用的许可保留队列和批准位。固定暂态类别相同不增加队列版本，类别、模式或原因实际改变才增加版本。异步检查期间队列变化会使该检查失效。缺少必需策略绝不授予许可。冻结链工作还会在已注册策略检查前后重读执行节点定义，覆盖派发及未完成开窗的执行或恢复。当前版本与冻结的 `expectedSeatRevision` 不同以 `revision-conflict` 拒绝执行；`remoteAdmission` 不再允许保留的发送节点、来源、主体或方法时以 `unauthorized` 拒绝，二者均不产生新的会话副作用。来源所有者与执行目标同机时执行相同检查，不刷新冻结版本、载荷摘要、操作标识或原凭证。精确回执重放保持不变。这些检查不使外部来源读取或定义写入与会话创建成为原子操作。

本地提供方可在引擎访问能力中注册 `preAdmit`。人工 `openWindow`（包括本地批量逐个发出的开窗）在触发接纳前等待此钩子。拒绝结果原样返回，不产生引擎接纳、资源或会话副作用；策略审计由钩子提供方负责。未注册钩子时原准入路径不变。

可信宿主通过 `seatAuthorizationIssuers` 注册捕获的身份与实时策略检查；调用方取得实例拥有的凭证，不从请求字段推导权限。`seatAuthorizationTransactions.transact` 将授权与匹配意图写入同一同步日志帧。每条提交的效果必须携带签发的操作标识。`approve` 在同帧提交队列变化，不调用旧批准方法；被拒批准重试时保留原拒绝结果，重新获得授权的尝试需要新的操作标识。撤销、外来、过期或不匹配的凭证均被拒绝。追加失败不接纳投影动作；同步结果不确定时，重试前必须恢复。

授权帧要求 `seat-authorization/v1`；旧解码器拒绝新判别值。支持该能力的恢复与只读快照在既有日志中保留事实。新查询包含 `plugin`；旧 `seatAuthorizationQueries.query` 跳过该种类并推进物理游标，绝不重标种类。查询按单、位、节点、种类及时间过滤，返回已提交水位、排他扫描游标与完整性。无归属的历史决策仍为 `legacy-unknown`。引擎效果查询与导出保留旧词表，不包含授权事实。独立 `seatAuthorizationExports.export` 服务序列化有限的 `seat-authorization/v1` JSON 分页，包含游标、水位、完整性和插件归属；在线引擎与离线读取器均提供此服务。

远端受理帧要求 `node-work-chain/v1`，并将 `node-route/accepted` 事实与匹配的签发授权、冻结触发意图写在同帧。重放校验完整来源身份、所有者代次、快照、改面占位和原操作；相同业务身份的第二次受理在追加前被拒绝。旧解码器拒绝整帧。保留的链输入隔离合并身份，并在每次派发时施加来源模式上限，恢复后亦如此。注入的路由回调发送器接收冻结的所有者路由；只有匹配的已提交回执才完成交付。没有失败诊断的匹配 owner 待决回执属于正常异步进度：outbox 保留退避并再次查询，不锁存引擎失败。发送器缺席或回执待决时保留重试，不退回同名本地来源；认证及协议失败暂停交付。`acceptFrozen` 核对本地签发的发送节点事实及目标许可列表，再将完整业务键、授权和冻结意图同次提交。精确重发先于新受理检查返回首次受理结果，即使目标定义或实时签发器已撤除；载荷变化报冲突。完整进程恢复从已提交帧重建该回执；被中断的帧不受理部分意图。可选 `nodeWorkChainBusiness` 注册等待日志及席位受理恢复，并提供完整键精确查询；恢复前报告未知。撤装拒绝旧引用发起的查询及冻结或批量写入，在资源释放前排空已受理调用；重装不能继承旧就绪状态。业务注册要求注册处与显式 `nodeWorkChain` 服务同时存在。缺少任一依赖时，引擎不创建链注册或链存储，普通回包保持不变。冻结派发要求已注册的许可复核，执行策略缺席时保留队列。生产出站授权装配仍归组合层。Loader 总是注入发送闭包，先选择冻结路由再获取服务。来源所有者、目标和回调执行节点均为本引擎时，只消费可选 `seatLocalCallbackOwner`，等待 `ready` 并核验当前可用性；提供方缺席或撤装绝不退回对端或来源回调。远端回调仍获取 `nodeWorkChain` 与 `nodeWorkChainRouter`，每次查询和交付均通过 `outboxIssuer` 获取新受限授权。后装及替换在既有引擎驱动周期生效。服务缺席保留 transient 重试，不创建链存储。首次发送前按完整业务键查询所有者；只有确认不存在才允许该次发送。派发前在既有回调日志记录 `responseClass: unknown`；抛错或超时在当次尝试中查询原完整键。远端明确待决回执保留 transient 重试；明确拒绝且 `effectState: none` 时保留原拒因及基线分类：认证或协议拒绝暂停，其他拒绝按 transient 重试。每次 transient 重试在业务发送前精确查询完整键；发送前的 unknown 标记不覆盖所有者明确结果。签发器撤回不能清除不确定性。unknown 后续尝试只做精确查询，绝不重发业务方法，即使所有者返回 missing。未知态保留在回调投影，`engine.operation` 通过 pending 进度及 `callback-outcome-unknown` 阻塞原因公开；只有原键已结算结果才能消除未知态。待决回执、授权不可用及断链保留原指数退避；只有所有者返回 `committed` 才完成交付。原路由、回调标识、载荷摘要和模型证据均不改变。

`queryRoutedCallback(engine: SeatEngine, request: NodeWorkChainOperationRequest): Promise<DeliverSourceCallbackRequest | undefined>` 等待日志恢复，仅在完整键各字段及 `payloadDigest` 全部匹配时，返回持久回调、路由和模型证据的独立副本。发送节点为本引擎，主体取自已受理路由，操作号为路由原操作号。查询不写存储，也不返回可复用授权。受限签发器还必须将请求正文及目标节点与持久正文比对，才能签发授权；无匹配不授予许可。未显式装链时，本地回调路径与存储保持不变。

包入口导出 `validSourceProxy(value: unknown)`，供私有组合校验完整保留的来源记录，无需导入未发布的 TypeScript 文件。它核验与日志恢复相同的身份、冻结证据和结果关联，不授予权限，也不执行写入。

`registerSourceProxy` 安装唯一进程内来源组合，处理远端触发受理及上下文开窗、唤醒。`target` 只选择归属，不预留工作；`prepare` 提供来源所有者持久保存的冻结快照、占位及原本地动作凭证。引擎核验该凭证，在调用 `send` 前通过必需的 `node-source/updated` 帧持久保存完整本地输入、冻结载荷、业务键及原归属。引擎不接收签发器。组合层持久保存发件箱意图，为精确载荷新签授权，并携匹配委托调用节点路由器。已确认结果予以保留；传输或结果持久化未知时保留原占位，不分配本地队列或资源。精确重试返回持久结果，未知意图可交可选的组合层 `reconcile` 对账；缺席时绝不盲目重发。注销拒绝新发送并排空已接纳工作。未注册时原本地路径及远端拒绝保持不变。

可选 `sourceWake: [{ sourceId, eventTypes }]` 为注册外部事件选择 `wakeSource(envelope)`，替代普通开窗入口。来源适配器在 `accept` 前调用此可选方法，并保留事件直至获得持久唤醒回执；返回 undefined 时选择原入口。事件必须携带原任务与开窗上下文，项目必须显式允许自动运行，来源代理必须解析到远端目标。准备端接收已注册来源事件，但只有既有受信组合才能签发原本地凭证；调用者提供的身份不构成权限。冻结 wire 方法编号、日志记录及接收端许可列表均不改变。`wakeSource` 是本地服务方法；`sourceWake` 与 `frozenWakeContext` 是本地配置，不是 wire 字段。兼容旧对端收到既有冻结请求；若将这些名称注入报文或载荷，旧严格解码器明确拒绝，不会静默授予权限或把它们作为授权忽略。缺少所需方法能力的对端在派发前拒绝。未知回执使用既有精确查询路径，绝不退回本机开窗。

可选 `frozenWakeContext: true` 在持久投递意图形成前，将冻结任务正文追加到已有窗唤醒模板后。完整消息必须符合 `maxSourceBytes`；省略时保留仅模板文本。既有消息发送器记录正文，并按确定性的操作与窗口标识去重。这些字段不授予方法、不绕过接收策略，也不解除预算停止的准入限制。

受信唤醒的选窗与无窗冻结开窗共用本地开窗受理槽；待排队或未完成的开窗阻止同席位再次回退开窗。有窗唤醒在私有 `node-wake/updated` 帧中同次持久保存原接收授权与确定性投递动作，不伪装触发效果；旧读取器拒绝此判别值。恢复时持久消息投递复用原 wire 操作与目标窗派生的标识，首次回执不可覆盖。精确重试保留原结果，输入变更报冲突，撤销凭证不能接纳新投递。恢复完成保留意图后，链查询才就绪；多窗选择及预算停存信回包保留本地唤醒语义。

节点批量保留相互独立的成员决策。每个 `node-batch/accepted` 事实要求 `node-work-chain/v1`，在同帧将原批载荷及签发授权绑定到唯一确定性成员动作。恢复拒绝不匹配的绑定并返回首次排队回执；后续成员中断不回滚已提交的前序成员。不签发新的本地凭证。

路由尝试失败时，可选外层 `lastDiagnostic` 与 attempted 交付在同次日志提交中持久保存，不改变回调正文或业务摘要。八个阶段为 `retained`、`issuer`、`local-query`、`local-dispatch`、`peer-query`、`peer-dispatch`、`owner-inbox` 和 `writeback`。原因标识匹配 `[A-Za-z0-9][A-Za-z0-9._/-]{0,127}`；说明非空、最多 512 个 UTF-8 字节且不含控制字符。不复制异常文本。完整决策帧仍受 `maxDecisionBytes` 约束，不截断；未知态写入失败禁止派发，诊断写入失败不能清除已保留的 unknown。成功只移除最新诊断，历史尝试不变；旧记录不补默认字段。既有 `engine.query` 按嵌套席位、关联任务和主任务过滤回调效果，保留有界分页和授权。操作身份冲突暂停而非重试。本地操作员通过 `engine.callbackResolve` 处置暂停的回调。可选观察本身不能作为部署降级依据：已保留的新方法证据仍要求兼容读取器。

路由回调在首次持久发布前冻结执行节点模型证据。已注册本地执行器提供记录中的模型或明确缺失证据；缺失时绝不退回档案配置。重放保留原证据与摘要，包括缺失观察。日志准入拒绝不一致的回调摘要、执行身份及替换已冻结证据的尝试。

`seatAuthorizationTransactions.operation` 从已提交队列及触发事实重建批准登记与关联开窗进度。待决理由、创建阶段、取消及已记录失败在重启后仍可查询，不执行工作，也不公开冻结指令。批准不等于创建成功或首轮成功。

授权 `cancel` 将 `queue/cancelled` 与签发授权、主体、种类、操作号、队列项、时刻、版本及可选原因同次提交。原因最多 512 个 UTF-8 字节且不能含控制字符。操作查询返回已结算取消回执；脱敏效果只保留原因是否存在。队列及操作索引各保留最近 256 条回执，更早的查询从已提交决策重建。待批和已批未派发项没有预算或资源占位，取消不创建也不改变这些投影。已派发、已开窗和未知目标保留 `revision-conflict` 类别并增加结构化 `cause.reasonCode`；无授权取消保留原字节和归属。取消本身不直接释放外部占位。完整冻结链的开窗前自动拒绝、到限及两种人工取消入口，在同一事务为每个原受理项追加唯一 `rejected` 回调；原路由、来源、操作号不变，人工回调使用固定安全原因而不携审计自由文本。只有原所有者认证接收后才能释放占位；离线、未知或暂停交付不代表已经释放。构造失败、写入失败或整帧超限不能只删除队列。

目录同步仅在 Windows 打开或刷新目录句柄时容忍 `EPERM`、`EISDIR` 和 `EINVAL`。文件写入、文件同步、目录关闭失败及全部非 Windows 失败仍向上抛出；这不保证 Windows 上不受支持的目录元数据同步已经完成。

已提交决策更新投影与发件箱交付。来源回调以稳定标识提供至少一次交付；凭据由来源注册提供，不存入引擎记录。dispose（资源释放）停止入口、排空自有工作、刷新日志并释放写入所有权。

<a id="callback-parking-and-operator-resolution"></a>
### 回调停车与操作员处置

本机来源缺席且在进入适配器前被拒绝时，若此前每次尝试也均已确认无效果，则持久保存 `lastDiagnostic.stage=retained` 与 `effectState=none`。反复缺源不会把该证据变成未知；随后明确无效果的认证拒绝仍仅影响该回调。先前部分、已提交、未知或缺失的效果证据继续保守保留，来源缺席和重启也不例外。本机来源异常使用 `lastDiagnostic.stage=local-dispatch`，固定 `cause.code` 为 `callback-unclassified-error`、`callback-timeout`、`callback-authentication-failed` 或 `callback-protocol-error`。不保存异常消息、堆栈或嵌套原因；未分类异常与超时保守报告副作用未知。关联标识先取持久路由操作号，再取开窗操作号，否则以 `callback/` 拼接规范化回调标识的 SHA-256 摘要；无会话回调也使用此规则。

每段连续 transient 的内建墙钟上限为 900000 ms，起点是首个已提交 `callback/attempted` 帧的 `observedAt`。重启、离线及暂态细码变化不重置；成功、认证、协议及最终 unknown 中断，attempt 未递增的发前 unknown 屏障既不起段也不断段。在 `nextDue` 与外部 I/O 前检查，调用完成后再核；成功优先于到限。I/O 前停车只追加一帧 attempted 转换，attempt 不变；实际调用后则在该次唯一 attempted 帧递增 attempt 并直接记录停车，不另写转换帧。两者均为 `phase=paused`、`nextDue=null`；保持停车期间，后续 drive 和重启对该回调零新帧。此规则独立于重试退避配置及开窗前保留注册。

远端传输 none、链路不可用及 hello 能力缺失以 `callback-link-unreachable-limit` 停车，其它失败用 `callback-transient-limit-reached`。既有路由缓存状态中的认证 hello 就绪观察，其 `observedAt` 必须严格晚于最近停车帧，才会令链路类自动恢复一次，码为 `callback-auto-resumed-on-link-ready`。再次停车须等待更新的观察，旧缓存 hello 不得再次恢复。目标 owner 须 connected、reachable 且声明 `node-work-chain/v1`；失败或重复 hello 不增加恢复帧。恢复帧起算新段，实际投递仍复核当前路由授权。其它类停车必须由操作员处置。

`engine.callbackResolve({ callbackId, action: 'resume' | 'abandon', expectedAttempt })` 要求当前本地操作员授权。resume 保留全部身份和正文，写 `callback-manually-resumed` 并开始新段；abandon 写 `callback-manually-abandoned` 和终态 `abandoned`，不声称 owner 已产生业务效果。只有同回调标识、同动作、同预期 attempt 的已执行处置帧之后没有新停车帧时，才读回现状、零帧重放；否则先拒非 paused，再比较 attempt。相同 attempt 上的新停车可以再次处置；未知回调、非 paused 和 attempt 冲突零帧拒绝。同组键为 `(sourceId, sessionId, triggerId)`：paused opened 挡住 ended；resume 后须等 opened delivered，abandon 后下一轮 drive 即可投 ended。见[受信命令行示例](../../host/host-admin/README.zh.md#callback-resolution)。

<a id="pre-open-terminal-outcomes-and-transient-retention-limit"></a>
### 开窗前终局与暂态上限

组合必须在对外准入前，对实际执行端实例的全部受信路由调用 `SeatEngine.registerPreopenRetention({ sourceId, sourceOwnerNodeId, limitMs, projectId? }): () => Promise<void>` 注册，并通过生命周期效果保留各撤装函数。`projectId` 可选：提供时只覆盖该项目，省略时覆盖冻结路由 `(sourceId, sourceOwnerNodeId)` 的全部项目。唯一的精确项目匹配优先于唯一的路由级匹配。任一层多重匹配，或两层均无匹配时，使用与组合缺省同值的内建 900000 ms 兜底上限。到限前这些项保留队列及 `provider-unavailable`，禁止开窗，保留固定安全诊断与引擎失败诊断，仍可受权人工取消；到限时沿已注册路由的同一终局取消及所有者回调路径处理。只用公开部署也可通过 `registerPreopenRetention` 设置其他限值，无须新增公开配置键。标识使用席位服务的品牌类型，注册限值为已解析配置中的正整数毫秒。复核提供方撤回不撤限值；组合撤装立即移除注册并等待当前驱动结束。限值大于兜底的组合须常驻注册：热重载撤注册窗口内，已超过 900000 ms 的旧项可能按兜底终局。

当前固定暂态类别的首个已提交帧 `observedAt` 为起点。批准、同类重试、合并及重启不重置，真实换类别另起一段；旧项首次写入固定类别才开始计时，不倒推。墙钟倒退不重置起点。独立检查先于执行器和外部读取，到限首轮以 `gate-denied`、`retryable=false`、`effectState=none` 同帧取消并通知；提供方或执行器缺席不能跳过。普通待批、关闭模式、预算和容量等待以及已派发工作不套此终局路径。

原来源操作查询及三种冻结精确业务查询在可证开窗前终局时返回既有 `settled` 内的 `rejected` 和原因；终局优先于回调运输未知。重复写仍返回首次受理回执；精确查询先核完整键和摘要，当前待决版本取真实队列版本。取消操作号仍返回原审计回执，通用终局结果不增加版本字段。

启动在发布就绪前从完整历史建立临时索引，对无任何执行及回调事实的可证冻结终局追加唯一回调帧，`causedBy` 指原取消事件；四类终局包括自动拒绝、容量准入明确拒绝、受权人工取消及旧无授权冻结取消。原帧不改、队列不复活，自动原因保留原 `retryable`；证据歧义不补并报告安全诊断，追加失败阻止启动完成。任何历史回调均交既有发件箱续投，不另造回调。

### 升级与回滚

来源所有者与执行端须使用成对验证版本及同一组合限值；先停止新来源准入，备份双方全部持久域和水位，先恢复所有者再启动执行端，核原身份、代次、授权及能力后自然对账。回调结清后再恢复新业务。不增加持久字段、公开配置键、wire 方法或能力位，已有帧结构可被兼容读取器理解，但旧实现仍可能错误取消或遗漏回调，能读不等于允许运行回滚。有活跃队列或未结清回调时保持完整新账本并前滚修复，禁止删除追加帧或恢复单边旧备份；已写入新方法证据的最低读取版本限制仍有效。

<a id="model-experience"></a>
## 模型体验

### 执行器拥有的工作

#### 模型看到什么

`seatEngine` 提供方不贡献工具 schema 或提示词。已注册执行器通过既有消息服务交付开场与预算通知。

#### Token 影响

准入和查询不使用模型 token。获准工作与缓存维护可通过各自提供方发起模型请求；计费包含后代工作与维护。

#### KV Cache 影响

查询和日志提交保留既有请求前缀。缓存维护是独立的提供方请求；结果未知的续期被保留，不会自动重放。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延后工作

- 失败监督暂停自动 drive 与决定通知，不封锁全部入站写入。准入、事务、策略与预算更新、子任务生命周期、人工续期或换窗、关闭记录及受权回调处置仍执行原有检查，也可能继续提交或产生原有效果。运维修复前须另行停止准入；不可用状态不是全局写屏障。不可恢复监督也会暂停开窗前自动到限处理和回调对账，直到修复后重启。
- `seatAuthorizedEngineActions` 将续期尝试及换窗队列与签发凭证同次提交；未携凭证时保留旧方法。准入前复核当前权限，历史回执不能派发另一动作。仅注册签发器不会接通命令行或全部自动入口；这些消费方仍需显式适配。
- 开窗和恢复需要注册本地执行器；证据缺失时工作保持待处理，不能虚构窗口。
- 活跃提供方拥有写入器和协调计时器；它不是离线只读查询提供方。
- 账户并发统计用于诊断，不是强制执行的账户限流器。
- M8b：有链回调 abandon 不修改 `chain-sent`，链层仍可对账原 owner 键。晚到的 owner `committed` 回执本身不解除 seat 预算停车：其它类仍需操作员处置，链路类仍需更新的 hello 就绪观察。这两个独立状态不意味着 owner `paused`；abandon 不代表 owner 终态回执。unknown 回调及永不返回的适配器不在暂态限时内。早于 `abandoned` 的读取器不能重放此状态；须保留完整账本并前滚，不删除转换帧。
